# Shruthi-1 on the M-VAVE FM-1 — project backup

Backup made 2026-11-24 for migration to another Claude account. It is a snapshot, not a release: nothing was
added or refactored while making it. Start with `PROJECT_STATUS.md` (where things stand) and `CLAUDE.md`
(context a new Claude needs).

## Purpose

Run the sound of Mutable Instruments' **Shruthi-1** (open source, AVR hybrid monosynth, GPL) on the
**M-VAVE FM-1**, a pocket 6-operator FM synthesizer whose open-firmware ecosystem is Felucca / fm1_open.
The owner's end goal: **build FM-1 firmware from the GitHub website on a phone** (GitHub Actions, no PC,
no manual ZIP uploads) and install it.

## What exists (all in `port/`)

1. **`shruthi_core.c/.h` — a plain-C99 port of the Shruthi voice.** 24 oscillator shapes (band-limited
   saw/square/triangle + PWM, CZ family, quad-saw pad, FM, wavetables 1-18 + user, 8-bit land, crushed sine,
   dirty PWM, filtered noise, vowel), sub oscillator, transient generator, two envelopes, two LFOs, the 12-row
   modulation matrix with CV operators, oscillator mixing operators (sum, sync, ring, xor, fuzz, crush, fold, bits,
   duo, ping-pong), portamento, and a loader for the real 92-byte factory patch format.
   `shruthi_tables.h` holds the lookup tables, generated by `gen_tables.py` from Shruthi's `resources.cc`.
2. **`fe/eng_shruthi.c` — `ENG_SHRUTHI`, a Felucca engine** (integer only, 12 presets) built on that core.
   It is the sound source only (2 oscillators, interval, mix, operator, filter); Felucca provides envelopes,
   LFOs, matrix, sequencer, arpeggiator.
3. **Tests that compare against the ORIGINAL Shruthi source**, compiled on a PC with the AVR hardware stubbed
   (`ref/`, `build_ref.sh`, `test_exact*.cc`, `test_voice.cc`) plus plain tests (`test_core.c`) and a host test for
   the Felucca engine built against the real `felucca_engine.h` + `dsp.c` (`fe/fe_shruthi_host.c`).
4. **`PORTING_NOTES.md`** — verified results, limits, known differences, integration steps.

## Architecture

```
Shruthi-1 source (C++/AVR, GPL) ──port──> shruthi_core.c  (C99, bit-exact vs original)
                                              │ SH_NO_FLOAT
                                              v
Felucca-Engines interface ──────────> fe/eng_shruthi.c  (ENG_SHRUTHI, Felucca engine, integer only)
                                              │   (NOT yet added to the Felucca firmware)
                                              v
Felucca firmware (JieLi AC79 / pi32v2) ──build.sh──> build/felucca.fwsc  ──web installer──> FM-1
```

Why Felucca: `fm1_open` (M-VAVE's official SDK) keeps its DSP in a sealed binary (`libfm1_engine.a`,
`sealed_audio_api: true`), so a new engine cannot be added there. Felucca has its own engine table and DSP.

## Technology stack

C99 (the port and engine; the FM-1 build uses JieLi's clang 4.0.1 for pi32v2); C++11 only for the PC comparison
harness; Python 3 (table generation, Felucca's build tools); GNU make; gcc/g++ on Linux for tests.
Felucca firmware build: Linux x86-64 (or Docker on macOS), JieLi toolchain (`tools/get_toolchain.sh`), JieLi AC79 SDK
(from gitee, tag `AC79NN_SDK_V1.2.1_2023-12-13`), Python `Pillow` + `fonttools`.

## Setup / restore

Needs Linux (or WSL) with `gcc`, `g++`, `make`, `python3`.

```sh
unzip shruthi-fm1-backup.zip && cd shruthi-fm1-backup
mkdir src && cd src
for z in ../upstream/*.zip; do unzip -q "$z"; done      # makes shruthi-1-master, avril-master, Felucca-*, ...
cd ../port
make all        # test + exact + voice + felucca  (several minutes; the voice comparison is the slowest)
```

The Makefile expects the source trees at `../src/<name>` as above (override with `SHRUTHI=`, `AVRIL=`,
`ENGINES=`). Expected end state of `make all`: pitch errors < 0.5 cent; "ALL PASSED"; oscillators 14520/14520
bit-exact; envelope and LFO 0 diverged; whole voice 512/512 runs, 128/128 patches; Felucca engine "ALL PASSED"
(plain and sanitizer builds); "float/double tokens in the engine translation unit: 0".

Building the actual FM-1 firmware is a separate, **not yet done** step: see `PROJECT_STATUS.md`.
